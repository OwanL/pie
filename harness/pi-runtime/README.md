# Private Pi runtime artifact

The root `package.json`, `pnpm-workspace.yaml` and **single shared `pnpm-lock.yaml`** own the production graph, including all four Pi workspace packages. The former npm bridge manifest/lock and `--refresh-lock` route are retired. Source provenance and acceptance status belong to the [productization plan](../../docs/plans/PIE-PRODUCTIZATION.md).

The [runtime builder](../../scripts/build/pi-runtime.mjs) consumes **already compiled Pi workspace output**; it does not compile or mutate it. It requires current `harness/pi/.cache/build.json` evidence matching source, shared lock/toolchain inputs, Node and compiled bytes. Build the workspace first, then select a new absolute directory beneath OS temporary storage:

```text
proto run node -- scripts/build/pi-workspace.mjs
proto run node -- scripts/build/pi-runtime.mjs --output <new-absolute-private-os-temp-directory>
```

For an isolated source-to-artifact route (no primary workspace writer or reader stop), use:

```text
proto run node -- scripts/build/pi-runtime.mjs --isolated --output <new-absolute-private-os-temp-directory>
```

This snapshots current Git-inventoried source and privately installs the shared frozen graph before compiling and running the same canonical deploy/role packing and verification. Snapshotting and independent dependency copies have moderate storage/work cost; this is not a speed claim. Installation defaults to `--offline`; an empty private store may fail. Explicit `--allow-network` permits dependency downloads, not toolchain acquisition. The already installed pinned Proto pnpm JS executable is resolved before private HOME and version-checked by the installer, then reused for deploy. No source-root or manifest overrides are accepted.

Logs identify owned scratch and its `provenance.json`; successful output retains `isolated-provenance.json`. Confirmed success cleans only workspace scratch; failure or uncertain child teardown retains it and any artifact output. This route does not publish, install Pie, alter sessions/data, or require stopping primary workspace readers. Real private pnpm qualification exercised frozen installation, staging hardlink detachment and full canonical role verification/smoke. A fresh whole `--isolated --allow-network` build is now also qualified (2026-10-11): the build exited 0 and independently verified runtime `dac40e8d…483234` / tooling `d50e553a…18047` with the private input fingerprint `747ad186…c8203e` equal to the captured private tree, private scratch was cleaned with the owned process tree closed, and 63 focused tests passed (55 route, 8 compiler-lifetime). Retained failure history is not resolved by this qualification: an earlier whole build exited 1 on an EPERM cleanup failure after completing verification/smoke, external SIGINT/abrupt-death compiler handling is unqualified (only the eight owned AbortSignal cancellation cases pass), and earlier uncertain nested-teardown receipts remain historical. See the [plan's retained evidence and limits](../../docs/plans/PIE-PRODUCTIZATION.md).

Use `proto run node -- scripts/development/inspect-workspace.mjs harness/pi` to inspect the primary workspace gate read-only; pass the isolated `harness/pi` root for a private workspace. Builder registrations include a fixed operation label, invocation UUID and owned output path. Legacy records without metadata remain unresolved; neither a missing PID nor age authorizes reclamation, and the snapshot is not lifetime proof.

The nonisolated builder holds a development reader through confirmed teardown and runs the root production pnpm deploy using pinned `.prototools` and `.npmrc` settings (hoisted layout, lifecycle scripts disabled). It materializes deployed `node_modules` as independent ordinary files, omitting pnpm layout metadata and `.bin` shims, adding the Pi MIT license, and rejecting symlinks/shared hardlinks. The full deployed SDK, including compiled output, declarations, maps, docs/examples, assets and native prebuilds, is retained unchanged in `pi-tooling`; no second resolver or dependency graph is installed.

Current inputs include the Git-aware Pi source inventory, root manifest, shared lock, workspace configuration, toolchain configuration and Node target. The builder checks input stability and deployed compiled-byte identity before packing, then checks the unchanged tooling compiler outputs again. Runtime retains SDK JavaScript paths and required assets, removes declarations, and inlines only supported adjacent source maps. Unsupported maps remain external. The qualified Mistral 2.2.6 root graph is bundled behind its original seven-export ESM interface; unsupported package-context or dynamic-import graphs fail qualification.

Output contains `pi-runtime/{manifest.json,node_modules/,tooling-reference.json}`, `pi-tooling/{manifest.json,node_modules/}`, `build-evidence.json` and owned `work/` scratch; failed output is retained for diagnosis. The reference binds the complete tooling identity into runtime hashes. Startup verifies runtime files; typechecking acquires and fully verifies tooling before use, and publication verifies both roles. Legacy unsplit artifacts remain supported. Keeping the full SDK separately increases total package storage; this reduces startup file verification, not total package size. There is no SDK cache.

Credential-free, network-denied offline smoke checks cover public/private imports, cross-package Pi/TypeBox identity, themes, Photon WASM, current-target native helpers and the local CLI `--offline --version`. Run the CLI directly with Node at `pi-runtime/node_modules/@earendil-works/pi-coding-agent/dist/cli.js`; no shim is required.

Private Windows-x64 split artifacts passed relocation, SDK/model parity, credential-free mocked Mistral flows, delivery typechecking and both headless host/browser smoke routes. A mock-extension schema-2 publication/acquisition verified runtime bytes without reading tooling bodies. This does **not** establish live-provider or session-semantic parity, real Electron or cold-start performance, installed publication/adoption, or permission to restart an installed host. Publishing split output requires a schema-2-capable selected loader; explicit `--activate` upgrades the immutable loader before generation selection.
