## B4 checkpoint 6 coverage blocker — resolved (working tree, 2026-09-25)

The 73.5% / 78.0% skill-pruner coverage aggregate was a measurement corruption, not a real shortfall. Node's cross-child coverage merge for this package is unreliable: the same test files produced nondeterministic line aggregates between 73.5% and 95.5% across identical runs, and cross-child unions silently DROPPED real coverage (e.g. `prepass.ts` measured 88.9% from an honest union but 58.2% when an ESM-transformed duplicate instance of the module graph participated). Two module graphs loaded twice per measurement caused the duplicates: the pinned-SDK discovery test loaded the real SDK's ESM import chain in-process, and the extracted SDK-discovery test's spawned worker inherited `NODE_V8_COVERAGE` and leaked its own ESM instances into the parent report. Remaining per-test-file ESM imports of owner sources created further per-child duplicate instances.

Fix (no threshold change, no coverage hidden, every test still runs in every suite):

- Extracted the pinned-SDK discovery regression into `harness/tool-and-skill-selection/test/sdk-discovery.test.ts` (spawn wrapper) plus `sdk-discovery-worker.ts` (spawned worker): the real-SDK ESM load runs in its own process and no longer reports coverage into the package's measurement (`NODE_V8_COVERAGE` stripped from the spawn environment).
- Converted the remaining owner-source test imports in the package (`config`, `logger`, `version`, `prepass-cache`, `llm-scorer`, `message-builders`, `request-capability-ports`) to the package's `require()` convention so the measurement process holds exactly one module instance per source file.
- `scripts/run-tests.mjs` gains an opt-in `singleProcessCoverage` for `skill-pruner`: coverage runs execute all test files in one serialized process (`--experimental-test-isolation=none`) so the coverage report comes from a single child and cannot be corrupted by node's cross-child merge. Fast (no-coverage) runs keep per-file processes.
